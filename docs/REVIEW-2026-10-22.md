## 3. Code-quality notes

- **Error handling.** All service failures go through `AppException(ErrorCode, …)` and the global filter; no `eslint-disable`, no `any` (`grep ": any|<any>|as any"` → 0). Gaps: unique-constraint races surface as 500 instead of 409 in payment capture (`payments.service.ts`, txn-ref pre-check outside the transaction) and in revenue type delete when a mapping/target FK blocks the hard delete (`revenue-types.service.ts:86`).
- **Validation.** Every DTO is class-validator decorated under the global `whitelist/forbidNonWhitelisted/transform` pipe. Missing: ROLLOVER sanity bounds (`readings.rules.ts:14-16`); CSV column order (`bulk-uploads.service.ts:141-143`).
- **Money.** No `Float` in `schema.prisma`; no `parseFloat`/`toNumber()` on money in services. The only `Number(...)` conversions are for statistics inputs (`alerts.service.ts:78-81`, `forecast.service.ts:56`), which is correct for z-scores and regression but should be commented as such.
- **Raw SQL.** Five `$queryRaw` uses, none bypassing audit: four `SELECT … FOR UPDATE` row locks (`audit.writer.ts:25`, `assessments.service.ts:254`, `payment-settlement.service.ts:168`, `bills.service.ts:174`) and the readiness probe (`health.service.ts:52`).
- **Permission decorators.** Every route handler has `@RequirePermission` or `@Public`, except the authenticated self-service routes (`GET /auth/me`, MFA enrol/confirm/disable, change-password) and `GET /events`, which derive scope from the token. Acceptable; worth a one-line comment on each.
- **Pagination.** Paginated: assessments, payments, payers, bills, accounts, readings, cycles, bulk uploads, alerts, targets, audit, users, notifications, reversals, GL mappings. Unpaginated reference lists: tariffs, SoD rules, roles, permissions, revenue types, system config — bounded tables, acceptable, but the brief's "high-volume" wording suggests documenting the bound.
- **Ownership checks** exist on every `/me/*` route (`self.controller.ts:54-93`, `statements.service.ts:35`, `bills.service.ts:82`, `payment-initiation.service.ts:64-70`). No e2e proves the 403 for a foreign account statement.
